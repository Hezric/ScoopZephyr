# Manifest updates

The [Excavator workflow](../../.github/workflows/excavator.yml) runs every four hours and can also be started manually. Scoop's official `checkver.ps1` checks versions and updates manifests. Before publishing, the workflow runs the existing `bin/test.ps1` Pester/Scoop suite with `CI=false` so it validates all working-tree manifests, including uncommitted updates. A test failure stops the run before any publishing API call. The workflow restores `.markdownlint.json`, which the shared test runner removes.

The [publisher](../../.github/scripts/excavator.ps1) creates a per-run `chore/update-apps-<run>-<attempt>` branch from the checkout SHA and commits each changed bucket manifest through GitHub's Contents API. GitHub creates the `github-actions[bot]` author and platform signature. Messages use `chore(bucket): update ` followed by the package and version in backticks. The publisher requires a Verified bot commit and stops on an API failure or a conflicting manifest change.

Updates made with `GITHUB_TOKEN` do not trigger push workflows. Excavator therefore explicitly dispatches `ci.yml` on the staging branch using `actions: write`. It waits up to 20 minutes for the exact SHA's GitHub Actions `test` and `policy` check runs to complete successfully. Those checks cover both PowerShell suites, publisher regression checks, and commit/branch policy. It then confirms the target branch still matches the checkout base and fast-forwards it to that same SHA with `force=false`. Main's strict checks, signatures, and linear-history rules apply without bypass actors.

Successful promotion deletes the staging branch. Failed checks, timeout, an API failure, or a concurrent target update leave main unchanged and retain staged work for inspection. The next scheduled run starts from current main; inspect a retained branch before manually deleting it. Workflow concurrency serializes Excavator runs per target branch. Manual dispatch on a development branch targets that branch, allowing compatibility checks before enabling the production main lock.

Run `.github/scripts/test-excavator.ps1` for payload, URI, and signature checks, and `.github/scripts/test-excavator-publish.ps1` for successful promotion and rejection of failed CI or concurrent target changes. GitHub API readback of signatures, checks, and the final main ref verifies the live integration.
