# Manifest updates

The [Excavator workflow](../../.github/workflows/excavator.yml) runs every four hours and can also be started manually. Scoop's official `checkver.ps1` checks versions and updates manifests. Before publishing, the workflow runs the existing `bin/test.ps1` Pester/Scoop suite with `CI=false` so it validates all working-tree manifests, including uncommitted updates. A test failure stops the run before any publishing API call. The workflow restores `.markdownlint.json`, which the shared test runner removes.

The [publisher](../../.github/scripts/excavator.ps1) creates a per-run `chore/update-apps-<run>-<attempt>` branch from the checkout SHA and commits each changed bucket manifest through GitHub's Contents API. Published JSON uses UTF-8 without BOM and LF newlines; Git checkout supplies CRLF for Scoop's tests. GitHub creates the `github-actions[bot]` author and platform signature. Messages use `chore(bucket): update ` followed by the package and version in backticks. The publisher requires a Verified bot commit and stops on an API failure or a conflicting manifest change.

Excavator opens an update PR using `pull-requests: write`. Repository Actions settings allow PR creation while default workflow permissions remain read-only. Native PR CI tests both PowerShell environments and runs commit-check on the actual PR title and every commit, alongside exact branch-name policy.

GitHub can place the bot-created native PR workflow in `action_required`. The publisher matches the exact CI workflow, PR event/number, repository, staging branch, and signed head SHA before approving that one run, once per run ID. It never approves unrelated workflows or PRs. Approval uses the existing `actions: write` permission and does not change repository-wide approval settings.

The publisher waits up to 20 minutes for that native PR run itself and the exact head SHA's GitHub Actions `test` and `policy` check runs to succeed. It confirms the target still matches the checkout base and the PR head, title, and base are unchanged, then requests a squash merge with an exact-head SHA guard. GitHub enforces main's strict checks, signatures, and linear history without bypass actors. The publisher reads back the resulting commit's Verified signature, confirms staging still has the checked head, and deletes the merged branch. An already-deleted branch is accepted; a changed staging head is preserved.

Failed checks, timeout, a concurrent target update, or an API rejection retain the PR and staged work for inspection. Read back PR/target state before retrying a failed transport operation. The next scheduled run starts from current main. Inspect retained work before deleting it. Workflow concurrency serializes Excavator runs per target branch; manual dispatch on a development branch targets that branch.

Run `.github/scripts/test-excavator.ps1` for payload, URI, and signature checks, and `.github/scripts/test-excavator-publish.ps1` for checked squash merging, owned native-CI approval, and cleanup/failure handling. GitHub API readback of the PR, checks, and resulting signature verifies the live integration.
